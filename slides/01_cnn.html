2 Learning from examples

2.1 What is learning, and why machine learning?

  • Learning: observations → learning → a skill
  • Machine learning: data → an algorithm → a skill
  • A skill improves a performance measure: earlier detection of disease, or today, finding where AGO2 binds
  • Define “tree” and write a program for it: hard. Learn trees from examples: a 3-year-old can do it
  • Ask the room for a definition before showing these.
  • A person learns from experience accumulated from observations; a machine learns from experience computed from data. Machine learning automates learning from data in order to predict or decide.
  • The performance measure makes “learning” testable: accuracy, or today the AUROC (section 3).
  • Writing down rules that recognise every tree is hard; showing examples is easy. The same holds for binding sites: nobody can write down the full rule for where AGO2 binds.

2.2 A short history

  • From Bayes’ theorem (1764) and Ada Lovelace’s first algorithm to AlphaGo (2016) and AlphaFold (2018).
  • The ideas are old; the data and computing power that make them work at scale are recent.

2.3 Statistics, machine learning and AI

  • Statistics: use data to make inferences about a population or a process
  • Machine learning: use data to find a function \(g\) that approximates an unknown target \(f\)
  • AI: compute something that shows intelligent behaviour
  • Use machine learning when
    • there is a pattern to learn
    • there is no easy rule to program it
    • there are data about it

Image: ResearchGate, publication 380790362

  • Click: the Venn diagram. Deep learning sits inside machine learning, inside AI; statistics overlaps with machine learning and with data science.
  • Statistics gives machine learning many of its tools; traditional statistics cares more about provable results under assumptions, less about computation.
  • Machine learning is one route to AI. Chess: traditional AI searches a game tree; machine learning learns from board positions.
  • When: all three hold for AGO2. Binding is not random (1), there is no simple rule for it (2), and CLIP-seq measured tens of thousands of sites (3). If (1) fails, there is nothing to learn; if (2) fails, write the rule; if (3) fails, there is nothing to learn from.

2.4 AI, machine learning, deep learning

2.5 Supervised learning

  • Examples \((x_i, y_i)\), \(i = 1, \dots, N\): a sequence \(x_i\) and its label \(y_i\) (1 bound, 0 unbound)
  • A model \(g_\theta\) with parameters \(\theta\) predicts \(\hat p = g_\theta(x)\), the probability of bound

  • Four real training sequences, the first 32 of their 340 letters. \(y\) is the CLIP-seq label; \(\hat p\) is the prediction of the CNN trained in this part.
  • Supervised learning: every training example comes with its answer. Here \(N\) = 92,346. The next slide names these symbols.
  • Training chooses \(\theta\) so that \(\hat p\) is close to \(y\) on the training examples. The goal is good predictions on sequences the model has not seen (section 3).
  • The second bound example gets 0.35 and the second unbound one 0.52: the model is often uncertain, and sometimes wrong.
  • Click: the loss of each example, small when \(\hat p\) is close to \(y\) (0.10 for the first, bound at 0.90) and large when it is far (1.04 for the second bound one, at 0.35). Slide 2.8 gives the formula.

2.6 Notation

Symbol Meaning
Input space \(\mathcal{X}\) what we observe
Output space \(\mathcal{Y}\) the answers
Training examples \(D = \{(x_i, y_i)\}_{i=1}^{N}\) inputs with known answers
Unknown target \(f: \mathcal{X} \to \mathcal{Y}\) the true input-to-answer relation
Hypothesis set \(\mathcal{H}\) the models we allow, \(g_\theta\) for every \(\theta\)
Learning algorithm \(\mathcal{A}\) how one \(g_\theta\) is picked
Final hypothesis \(g_\theta \approx f\) the trained model
  • The notation we use from here on. \(f\) is unknown: we only see it through the examples. The algorithm picks one \(g_\theta\) from \(\mathcal{H}\).
  • Today: \(\mathcal{X}\) RNA sequences; \(\mathcal{Y}\) 1 bound, 0 unbound; \(D\) 92,346 labelled sequences; \(f\) where AGO2 binds; \(\mathcal{H}\) all CNNs of one shape; \(\mathcal{A}\) gradient descent; \(g_\theta\) the trained CNN.

2.8 The loss

Binary cross-entropy

\(\mathcal{L} = -\frac{1}{N}\sum_{i} \big[\, \color{#1A73E8}{y_i \log \hat p_i} + \color{#BDC1C6}{(1 - y_i)\log(1 - \hat p_i)} \,\big]\)

\(\mathcal{L} = -\frac{1}{N}\sum_{i} \big[\, \color{#BDC1C6}{y_i \log \hat p_i} + \color{#E8710A}{(1 - y_i)\log(1 - \hat p_i)} \,\big]\)

  • One example’s contribution to the loss, against the predicted probability. First a bound example, \(-\log \hat p\), the blue term of the formula. Click: an unbound example, \(-\log(1 - \hat p)\), the orange term.
  • A confident correct prediction costs almost nothing; a confident wrong one costs a lot (\(-\log 0.01 = 4.6\)).
  • On slide 2.5: predicting 0.90 for a bound sequence gives a loss of 0.10; predicting 0.35 gives 1.04.
  • Predicting 0.5 for everything gives \(\ln 2 = 0.69\), the loss of a coin flip.
  • For predicting a number one would use the mean squared error. Cross-entropy is the standard loss for a predicted probability.

2.9 Features: chosen or learned

  • A model needs numbers. Classic machine learning: we decide which numbers describe a sequence, its features, and the model learns how to weigh them.
  • Our first model uses two features of one real bound sequence: its GC fraction (0.40) and its U fraction (0.28). Why these two: slide 1.2 showed that bound sequences are richer in A and U than unbound ones (mean GC 0.41 against 0.45), so they are the obvious first guess, and two numbers can be drawn on a slide.
  • Click: deep learning gives the model the raw letters (one-hot, section 4) and lets it learn its own features during training. In a CNN these are the filters: real filters of our trained network are shown, blue positive and orange negative weights.
  • Nobody told the CNN to look at GC. Part 3 checks how much of what it learned is composition anyway.

2.10 The sigmoid: from a score to a probability

  • A model first computes a score \(z\), any number (a weighted sum of the features plus a bias). The sigmoid turns it into a probability between 0 and 1.
  • Score 0 means 0.5, no preference; the larger the score, the closer to 1 (bound); the more negative, the closer to 0 (unbound).
  • Every model today ends with a sigmoid. The score before it is called the logit.

2.11 The data in two numbers

  • 3,000 of our training sequences, one point each, placed by two numbers: the fraction of their letters that are G or C (x axis) and the fraction that are U (y axis). Blue bound, grey unbound.
  • The two clouds overlap heavily, but bound sequences sit a little lower on GC (towards the left).
  • The question for the next slide: can a straight line separate blue from grey better than chance? Logistic regression finds the best such line by gradient descent.

2.12 Gradient descent

  • The update: \(\theta\) are all the parameters, \(\mathcal{L}\) the loss, \(\eta\) the learning rate. Start from some \(\theta\), compute the gradient of the loss with respect to every parameter, move each parameter against its gradient, scaled by \(\eta\), and repeat.
  • Left and middle: 3,000 training sequences, one point each, placed by their two features, GC fraction and U fraction (previous slides); blue bound, grey unbound. The orange line is where the predicted probability equals 0.5: at step 0 (a deliberately bad start), after one step, and after 300 steps. Each title gives that step’s \(w_1\), \(w_2\) and \(b\). Right: the loss at each step.
  • The smallest possible model on our data: two features per sequence and three parameters (two weights and a bias).
  • The loss (slide 2.8) falls from 0.77 at the bad start to 0.67.
  • How well these two numbers separate the classes on held-out data: AUROC 0.66 (part 3).
  • Our CNN has 2,491 parameters. The genome models have millions to billions.
  • The learning rate \(\eta\) sets the size of each step (right). Same model and start, three learning rates: \(\eta\) = 0.05 moves too slowly; \(\eta\) = 0.5 is the run on the left; \(\eta\) = 10 overshoots the minimum and the loss jumps up and down.
  • The learning rate is set before training, a hyperparameter, and chosen on validation data (section 3). The notebook uses Adam with \(\eta\) = 0.001.

2.13 Mini-batches and epochs

  • Each step uses a batch of 256 sequences; an epoch is one pass over all 92,346 (360 steps)
  • The CNN of this part, trained as in the notebook: 10 epochs, 3,600 steps. Light blue: the loss on each batch. Dark blue: the mean over each epoch.
  • The gradient on one batch estimates the gradient on the whole training set. One batch is quick to compute, which allows many steps per epoch. The estimate changes from batch to batch, which is why the light line jumps (0.38 to 0.61 within the last epoch). This is mini-batch, or stochastic, gradient descent.
  • The epoch means fall from 0.61 to 0.44, most of it in the first three epochs.
  • 92,346 / 256 gives 360 full batches; the notebook drops the incomplete last one (drop_last=True) and reshuffles the order every epoch.

2.14 ReLU

  • ReLU (rectified linear unit) keeps positive values and sets negative ones to 0.
  • It introduces non-linearity. Without it, a stack of weighted sums is just one weighted sum, a straight boundary like logistic regression.
  • In the CNN, ReLU after a filter means: a window that does not resemble the filter gives 0, a window that does gives a positive value (slide 4.4).

2.15 From logistic regression to a neural network

  • A neural network stacks layers of units, with ReLU between them
  • Left: logistic regression is one unit, a weighted sum of the inputs plus a bias, then the sigmoid.
  • Right: a hidden layer of units, each a weighted sum followed by ReLU, feeds the output unit.
  • Without the nonlinearity, stacked weighted sums add up to a single weighted sum, which is no more expressive than logistic regression.
  • Training is the same as on slide 2.12. loss.backward() computes the gradient for every weight in every layer by the chain rule (backpropagation), and the optimizer takes the step.
  • The CNN of section 4 is a network of this kind in which each first-layer unit looks at a 10-letter window.

3 Testing a model

3.1 Train, validate, test

  • An epoch is one pass over the training data.
  • The 1,000 held-out sequences are 500 bound and 500 unbound; parts 1 and 2 use them as the test set. The bar is not to scale: the test set is about 1% of the data.
  • Never grade a model on the data it was trained on.
  • The notebook prints the held-out AUROC after every epoch, so we do look at the test set during training. That is acceptable for a workshop as long as nobody picks the best epoch by it; in a real project that is the validation set’s job.
  • The split is random by sequence. We checked for near-duplicates: 47% of held-out bound sequences have a training sequence within 150 letters on the genome (13% of unbound). On the 698 held-out sequences without one, the CNN scores 0.85 instead of 0.86, so the effect on our results is small. Real projects split by gene or chromosome.
  • Click: why not the training loss?
  • A larger CNN (about 230,000 weights) trained on only 1,000 sequences, so the effect is easy to see. Loss after every epoch on its training sequences (blue) and on the 1,000 held-out sequences (orange).
  • The training loss keeps falling, to almost 0: the model memorises its 1,000 examples.
  • The held-out loss falls until epoch 18, then rises: from there on, what the model learns about its training examples does not carry over to new sequences.
  • The training loss only says how well the model fits what it has seen. What we want is a model that works on sequences it has not seen, so we measure on held-out data.

3.2 Drawing the ROC curve

The scores of our convolutional neural network (CNN, section 4) on the 1,000 held-out sequences

  • The CNN of section 4 on the 1,000 held-out sequences: its scores, bound in blue and unbound in grey.
  • Pick a threshold: every sequence above it is called bound. True positive rate: the fraction of bound sequences above the threshold. False positive rate: the fraction of unbound sequences above it. One threshold gives one point on the right.
  • Threshold 0.8: 46% of bound and 4% of unbound sequences are above it. Click: 0.5 gives 75% and 21%. Click: 0.2 gives 94% and 53%.
  • Lowering the threshold catches more bound sequences and also lets in more unbound ones: both rates go up together. The question is how fast each one rises.
  • For anyone who knows diagnostic tests: sensitivity against 1 minus specificity.

3.3 AUROC

  • All thresholds together give the ROC curve (receiver operating characteristic). AUROC is the area under it: the probability that a random bound sequence scores higher than a random unbound one. 0.5 is chance, 1.0 is perfect.
  • Every threshold from 1 down to 0 adds a point; joined, they give the curve. The dashed diagonal is a model that ranks at random.
  • The area is 0.86 for our CNN: pick one bound and one unbound held-out sequence at random, and 86% of the time the bound one gets the higher score.
  • It does not depend on one threshold, so it compares models fairly. It says nothing about why a model scores well.
  • The loss is what training lowers, and it is computed on the training data. The AUROC measures what we want, separating bound from unbound, on held-out data.

4 The convolutional neural network (CNN)

4.1 One-hot encoding (TODO-1)

  • One column per letter, with a 1 in its row; padding columns of 0.25 up to 501
  • Each column is one letter; the four rows are A, C, G, U, and the coloured cell holds the 1. A sequence becomes a 4 × length matrix. The longest sequence is 375 letters.
  • A padding column of 0.25 means “unknown letter”: each base equally likely. 501 is the input width used by Pan and Shen, whose CNN this one follows.
  • If asked why not A=1, C=2, G=3, U=4: that would impose an order (G “greater than” C) with no biological meaning. One-hot keeps the four letters equally far apart.
  • TODO-1 writes the conversion: one_hot for one sequence (TODO-1a), then encode_batch for a list of sequences (TODO-1b). A test cell checks 201 sequences, including padding and an unknown letter. The rest of the notebook uses the students’ own encode_batch.

4.2 A filter slides along the sequence

  • A toy filter of width 4 on an 8-letter sequence, one click per position. The filter has one weight per letter and position (blue positive, orange negative) and a bias.
  • At each position the window picks, in every column, the weight of the letter that is there (the 1 in the one-hot column). Their sum plus the bias is the output; ReLU turns negative outputs into 0.
  • The filter’s weights favour A, C, G, U in that order: on the window ACGU it gives 2.4, elsewhere 0.
  • Five windows give five outputs. The real CNN does the same with filters of width 10 on 501 positions.
  • The same toy filter comes back in section 5, when we read what a filter likes.

4.3 Training changes the filters

  • One filter at epochs 0, 1, 3 and 10 of one training run (its number is in the figure), one epoch per click, with the held-out AUROC after each epoch. Rows A, C, G, U; columns the 10 positions; blue positive, orange negative weights.
  • Epoch 0 is the random initialisation (AUROC 0.58). After epoch 1 the model reaches 0.79 and after epoch 3 0.84. By epoch 10 the filter has clear preferences (the darkest cells: a letter at a position) and the model reaches 0.86. The exact numbers vary from run to run.
  • Each step is the update of slide 2.12, applied to all 2,491 weights. We use Adam, a variant of gradient descent that adapts the step size per weight.

4.4 The filter along one sequence

  • A real filter of our trained CNN (filter 7, which prefers U-rich windows): its output at every position of one bound sequence, after ReLU. x: position; y: output.
  • ReLU (slide 2.14) sets negative outputs to 0, so most positions give 0. Windows that resemble the weights give large values. The highest one is drawn in dark blue and its 10 letters are printed.

4.5 Channels and pooling

  • 10 filters give 10 output rows, channels; max pooling keeps the largest of every 3 positions

  • Click by click: the track of slide 4.4 as bars, then the same numbers as one row of colour, then all 10 filters, then max pooling.
  • One bound sequence of 340 letters, the one on slide 4.4, positions 210 to 330 (filter 7 peaks at 273). Top: the output of all 10 first-layer filters after ReLU at each position; darker blue is larger. Bottom: after max pooling, one value per block of 3 positions.
  • Each row is one filter’s track; row 7 is the track of slide 4.4.
  • The network computes all 492 positions of the padded input (164 after pooling); the figure shows 120 of them.
  • Pooling shortens each track threefold and keeps the strongest responses; the exact position within each block of 3 is lost. It has no parameters.
  • The second convolution reads all 10 channels at once: each of its 20 filters is 10 × 5, one weight per channel and pooled position.

4.6 A classic CNN: LeNet-5

LeNet-5 (LeCun et al., 1998) reads handwritten digits. Image: Zhang, Lipton, Li and Smola, Dive into Deep Learning, CC BY-SA 4.0, via Wikimedia Commons

  • One of the first CNNs: a 28 × 28 image of a handwritten digit in, one score per digit (10) out. The same parts as ours.
  • Convolution: 6 filters of 5 × 5, so 6 feature maps of 28 × 28 (the image is padded by 2 so the size stays).
  • Pooling: every 2 × 2 block becomes one number, 6 × 14 × 14.
  • Convolution again: 16 filters, each reading all 6 maps, 16 × 10 × 10; pooling, 16 × 5 × 5.
  • Flatten: 16 × 5 × 5 = 400 numbers, then three linear (dense) layers: 120, 84, and 10 scores.
  • For our sequences (next slide and notebook TODO-2): the input is a 4 × 501 one-hot matrix, the first filters are 4 rows tall so they read whole letters, pooling runs along the sequence only, and the end is one number, the logit.
  • Click: the table, LeNet-5 against ours, part by part.
  • The notebook prints LeNet-5’s shapes layer by layer with show_shapes.

4.7 Build your network (TODO-2)

  • The parts: a convolution slides its filters along the sequence (one output row, a channel, per filter); ReLU sets negative values to 0; max pooling keeps the largest value of each block of neighbouring positions, so the rows get shorter; flatten lays everything out in one row; a linear layer makes one number, the logit.
  • Two rules: the first filters cover all 4 letter rows, and the network ends with one number per sequence. Everything else is the students’ choice; the notebook prints the shape after every layer (show_shapes), which tells them how many inputs the linear layer needs.
  • Our reference network, used on the results slides: 10 filters of 4 × 10, ReLU, pooling by 3; 20 filters covering 5 pooled positions, ReLU, pooling by 3; flatten (20 × 53 = 1,060 numbers); linear to one logit. 2,491 parameters: 410 in the first convolution, 1,020 in the second, 1,061 in the linear layer.
  • Shapes in our network: 4 × 501 → 10 × 492 → 10 × 164 → 20 × 160 → 20 × 53 → 1,060 → 1. A convolution shortens a row by the filter width minus 1; pooling by 3 divides its length by 3.
  • No sigmoid inside the network: the loss (BCEWithLogitsLoss) applies it.
  • Students who finish early can try other networks and compare their held-out AUROCs.

5 Look inside

5.1 Which windows does a filter like?

  • The toy filter of slide 4.2, on three sequences: its output at each of the 5 positions of each sequence.
  • We do not read the weights; we watch the filter work. A high output means the filter met a window it likes.
  • One click per position: the blue window is the 4 letters the filter reads, and its output for that window appears in the column. Five positions fit in an 8-letter sequence.
  • Last click: a filter’s cutoff sits halfway between its mean output and its maximum, over all sequences and positions. Every position above it is a hit; here two of the 15.
  • The hits are the 4 letters starting at that position: ACGU in sequence 1 and UCGU in sequence 3.

5.2 From hits to a logo

PWM: position weight matrix, the frequency of each letter at each position

  • The hits are aligned: both start where the filter fired, so their first letters correspond. Stack them and count the letters at each position: the position weight matrix (PWM).
  • The logo draws the PWM as letters. A letter’s height is its frequency times the information at that position: 2 bits when the position always has the same letter, 0 when all four are equally frequent.
  • Position 1 is A half the time and U half the time, so it carries 1 bit; positions 2 to 4 always have the same letter, 2 bits.
  • With a real filter there are thousands of hits instead of two.

  • The question to leave with the room: if the score goes up, is it the pattern or only the letters each copy adds (a U-rich motif adds U letters)? The students design the control in TODO-5b; the notebook states this problem and hints at building it from the motif’s own letters.
  • The intended control is the same letters in another order, inserted at the same places: the difference between the two curves is then what the letter order adds.
  • This turns a logo, which is only a description of what a filter responds to, into an experiment on the whole model’s output.

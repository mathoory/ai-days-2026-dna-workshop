1.5 RNA, microRNA and AGO2

  • Projected: 2 min (a recap if the opening lecture covered it).

2 Learning from examples

2.1 Supervised learning

  • Examples \((x_i, y_i)\), \(i = 1, \dots, N\): a sequence \(x_i\) and its label \(y_i\) (1 bound, 0 unbound)
  • A model \(f_\theta\) with parameters \(\theta\) predicts \(\hat p = f_\theta(x)\), the probability of bound
  • Four real training sequences, the first 32 of their 340 letters. \(y\) is the CLIP-seq label; \(\hat p\) is the prediction of the CNN trained in this part.
  • Supervised learning: every training example comes with its answer. Here \(N\) = 92,346.
  • Training chooses \(\theta\) so that \(\hat p\) is close to \(y\) on the training examples. The goal is good predictions on sequences the model has not seen (section 3).
  • The second bound example gets 0.35 and the second unbound one 0.52: the model is often uncertain, and sometimes wrong.
  • Tutorial 1 notation, for those who took the course: input space \(\mathcal{X}\) (sequences), output space \(\mathcal{Y} = \{0, 1\}\), hypothesis set \(\mathcal{H}\) (all CNNs of one architecture), final hypothesis \(g\) (the trained CNN).

2.2 The loss

  • Binary cross-entropy: \(\;\mathcal{L} = -\frac{1}{N}\sum_{i} \big[\, y_i \log \hat p_i + (1 - y_i)\log(1 - \hat p_i) \,\big]\)
  • One example’s contribution to the loss, against the predicted probability. Blue: a bound example, \(-\log \hat p\). Grey: an unbound example, \(-\log(1 - \hat p)\).
  • A confident correct prediction costs almost nothing; a confident wrong one costs a lot (\(-\log 0.01 = 4.6\)).
  • On slide 2.1: predicting 0.90 for a bound sequence gives a loss of 0.11; predicting 0.35 gives 1.05.
  • Predicting 0.5 for everything gives \(\ln 2 = 0.69\), the loss of a coin flip.
  • Tutorial 1 used the mean squared error, for predicting a number. Cross-entropy is the standard loss for a predicted probability.

2.3 Gradient descent

\[\theta \leftarrow \theta - \eta \, \nabla_\theta \mathcal{L}\]

  • On our data: \(\;\hat p = \sigma(w^\top x + b)\), \(\;x\) = (G+C fraction, U fraction)
  • The update: \(\theta\) are all the parameters, \(\mathcal{L}\) the loss, \(\eta\) the learning rate. Start from some \(\theta\), compute the gradient of the loss with respect to every parameter, move each parameter against its gradient, scaled by \(\eta\), and repeat.
  • Left and middle: 3,000 training sequences, one point each, placed by G+C fraction and U fraction; blue bound, grey unbound. The black line is where the predicted probability equals 0.5, at step 0 (a deliberately bad start) and after 300 steps. Right: the loss at each step.
  • The smallest possible model on our data: two features per sequence and three parameters (two weights and a bias).
  • \(\sigma(z) = 1/(1+e^{-z})\) turns any score into a probability between 0 and 1. Every model today ends with a sigmoid.
  • The loss (slide 2.2) falls from 0.77 at the bad start to 0.67.
  • How well these two numbers separate the classes on held-out data is measured on slide 3.3 (AUROC 0.66).
  • Our CNN has 2,491 parameters. The genome models have millions to billions.

2.4 The learning rate

  • \(\eta\) sets the size of each step
  • The model of slide 2.3, from the same bad start, trained with three learning rates. Training loss after each step.
  • \(\eta\) = 0.05: every step goes downhill, but after 40 steps the loss is still 0.72.
  • \(\eta\) = 2: the loss reaches 0.67 within a few steps.
  • \(\eta\) = 10: each step overshoots the minimum, and the loss jumps between 0.7 and 1.75.
  • The learning rate is set before training, a hyperparameter, and chosen on validation data (section 3). The notebook uses Adam with \(\eta\) = 0.001.

2.5 Mini-batches and epochs

  • Each step uses a batch of 256 sequences; an epoch is one pass over all 92,346 (360 steps)
  • The CNN of this part, trained as in the notebook: 10 epochs, 3,600 steps. Grey: the loss on each batch. Black: the mean over each epoch.
  • The gradient on one batch estimates the gradient on the whole training set. One batch is quick to compute, which allows many steps per epoch. The estimate changes from batch to batch, which is why the grey line jumps (0.38 to 0.61 within the last epoch). This is mini-batch, or stochastic, gradient descent.
  • The epoch means fall from 0.61 to 0.44, most of it in the first three epochs.
  • 92,346 / 256 gives 360 full batches; the notebook drops the incomplete last one (drop_last=True) and reshuffles the order every epoch.

2.6 From logistic regression to a neural network

  • A neural network stacks layers of units, with ReLU, \(\max(0, z)\), between them
  • Left: logistic regression is one unit, a weighted sum of the inputs plus a bias, then the sigmoid.
  • Right: a hidden layer of units, each a weighted sum followed by ReLU, feeds the output unit.
  • Without the nonlinearity, stacked weighted sums add up to a single weighted sum, which is no more expressive than logistic regression.
  • Training is the same as on slide 2.3. loss.backward() computes the gradient for every weight in every layer by the chain rule (backpropagation), and the optimizer takes the step.
  • The CNN of section 4 is a network of this kind in which each first-layer unit looks at a 10-letter window.

3 Testing a model

3.1 Train, validate, test

  • Train: fit the weights
  • Validation: choose settings, such as the number of epochs
  • Test: report once
  • Today: 92,346 training and 1,000 held-out test sequences
  • An epoch is one pass over the training data.
  • The 1,000 held-out sequences are 500 bound and 500 unbound; parts 1 and 2 use them as the test set.
  • Never grade a model on the data it was trained on.
  • The notebook prints the held-out AUROC after every epoch, so we do look at the test set during training. That is acceptable for a workshop as long as nobody picks the best epoch by it; in a real project that is the validation set’s job.
  • The split is random by sequence. We checked for near-duplicates: 47% of held-out bound sequences have a training sequence within 150 letters on the genome (13% of unbound). On the 698 held-out sequences without one, the CNN scores 0.85 instead of 0.86, so the effect on our results is small. Real projects split by gene or chromosome.

3.2 AUROC

  • AUROC = the probability that a random bound sequence scores higher than a random unbound one. 0.5 is chance, 1.0 is perfect.
  • These are the scores of the CNN we build in the next section; for now it is any model that outputs a probability.
  • Left: the CNN’s scores on the 1,000 held-out sequences, bound in blue and unbound in grey.
  • Right: each threshold on the left gives one true positive rate (the fraction of bound sequences above it) and one false positive rate (the fraction of unbound sequences above it), one point on the curve. The dashed diagonal is chance. The area under the curve is the AUROC, 0.86 here.
  • It does not depend on a threshold, so it compares models fairly. It says nothing about why a model scores well.
  • For anyone who knows diagnostic tests: this is the ROC curve, sensitivity against 1 minus specificity.

3.3 Noise in a held-out AUROC

  • On 1,000 test sequences, 95% of resampled AUROCs fall within about ±0.025
  • One row per model, all scored on the same 1,000 held-out sequences. The dot is the AUROC. Resample the 1,000 test sequences with replacement 2,000 times; the bar covers 95% of the resulting AUROCs.
  • Three models from today: the CNN 0.86 (0.84 to 0.88), logistic regression on 5-letter word counts 0.74 (0.71 to 0.77), and on the two composition numbers of slide 2.3 0.66 (0.63 to 0.69). The bars do not overlap, so these differences are larger than the sampling noise.
  • The bars describe one model at a time. Two models scored on the same sequences make correlated errors, so their difference varies less than the bars suggest; a paired bootstrap measures it. Overlapping bars mean there is no evidence of a difference; they do not show that the models are equal.
  • Rule of thumb: on 1,000 test sequences ignore differences below about 0.03; on 3,000 (part 3), below about 0.02.

3.4 Overfitting

  • A model that scores much higher on its training data than on held-out data has overfit: it memorised its training examples. Report the held-out score
  • The same model, logistic regression on 5-letter word counts, scored two ways. Light bars: AUROC on its own training sequences. Black bars: AUROC on the 1,000 held-out sequences.
  • Left: 12,000 training sequences with regularisation. 0.82 on its own training data, 0.74 held out. A small gap is normal.
  • Right: 600 sequences and almost no regularisation. 1.00 on its training data, 0.67 held out.
  • Underfitting is the opposite: a model too simple for the pattern scores low on both its training data and held-out data.
  • Regularisation penalises large weights, which limits how closely a model can fit its training data.
  • In any evaluation code, including code an AI assistant wrote, check first which data the score was computed on.

4 The CNN

4.1 One-hot encoding (TODO-1)

  • One column per letter, with a 1 in its row; padding columns of 0.25 up to 501
  • Each column is one letter; the four rows are A, C, G, U, and the dark cell holds the 1. A sequence becomes a 4 × length matrix. The longest sequence is 375 letters.
  • A padding column of 0.25 means “unknown letter”: each base equally likely. 501 is the input width used by Pan and Shen, whose CNN this one follows.
  • If asked why not A=1, C=2, G=3, U=4: that would impose an order (G “greater than” C) with no biological meaning. One-hot keeps the four letters equally far apart.
  • TODO-1 writes the conversion: one_hot for one sequence (TODO-1a), then encode_batch for a list of sequences (TODO-1b). A test cell checks 201 sequences, including padding and an unknown letter. The rest of the notebook uses the students’ own encode_batch.

4.2 A filter computes a dot product

  • The same 40 weights at every position: weight sharing
  • A real learned filter (filter 7) from the trained CNN, applied to the real window where it responds most strongly. The slides from 4.6 on use filter 0.
  • Left: the filter, a 4 × 10 matrix of weights, one per letter and position; blue positive, grey negative. Right: the one-hot window.
  • Multiplied element by element with the one-hot window, the filter keeps one weight per position: the weight of the letter that is there (the number under each column). Their sum plus a bias is the filter’s output at that position (bottom line).
  • The same 40 weights are applied at every one of the 492 positions. Sharing the weights across positions makes it a convolution. A fully connected layer from the same 4 × 501 input to the same 492 outputs would have 4 × 501 × 492 = 985,968 weights.
  • This filter prefers U-rich windows, and its strongest response is only 1.07 times larger on bound than on unbound sequences. It responds to something common in both classes. Part 3 tests composition effects of this kind with a shuffle and with matched data.

4.3 The filter along one sequence

  • The same filter (filter 7): its output at every position of one bound sequence, after ReLU. x: position; y: output.
  • ReLU (slide 2.6) sets negative outputs to 0, so most positions give 0. Windows that resemble the weights give large values. The highest one is drawn dark and its 10 letters are printed.

4.4 Channels and pooling

  • 10 filters give 10 output rows, channels; max pooling keeps the largest of every 3 positions
  • One bound sequence of 340 letters, the one on slide 4.3, positions 210 to 330 (filter 7 peaks at 273). Top: the output of all 10 first-layer filters after ReLU at each position; darker blue is larger. Bottom: after max pooling, one value per block of 3 positions.
  • Each row is one filter’s track; row 7 is the track of slide 4.3.
  • The network computes all 492 positions of the padded input (164 after pooling); the figure shows 120 of them.
  • Pooling shortens each track threefold and keeps the strongest responses; the exact position within each block of 3 is lost. It has no parameters.
  • The second convolution reads all 10 channels at once: each of its 20 filters is 10 × 5, one weight per channel and pooled position.

4.5 Build your network (TODO-2)

  • Build it from these parts; you choose how many blocks, how many filters and how wide
  • The parts: a convolution slides its filters along the sequence (one output row, a channel, per filter); ReLU sets negative values to 0; max pooling keeps the largest value of each block of neighbouring positions, so the rows get shorter; flatten lays everything out in one row; a linear layer makes one number, the logit.
  • Two rules: the first filters cover all 4 letter rows, and the network ends with one number per sequence. Everything else is the students’ choice; the notebook prints the shape after every layer (show_shapes), which tells them how many inputs the linear layer needs.
  • Our reference network, used on the results slides: 10 filters of 4 × 10, ReLU, pooling by 3; 20 filters covering 5 pooled positions, ReLU, pooling by 3; flatten (20 × 53 = 1,060 numbers); linear to one logit. 2,491 parameters: 410 in the first convolution, 1,020 in the second, 1,061 in the linear layer.
  • Shapes in our network: 4 × 501 → 10 × 492 → 10 × 164 → 20 × 160 → 20 × 53 → 1,060 → 1. A convolution shortens a row by the filter width minus 1; pooling by 3 divides its length by 3.
  • No sigmoid inside the network: the loss (BCEWithLogitsLoss) applies it.
  • Students who finish early can try other networks and compare held-out AUROCs against the ±0.025 noise.

4.6 Training changes the filters

  • Filter 0 at epochs 0, 1, 3 and 10 of one training run, with the held-out AUROC after each epoch. Rows A, C, G, U; columns the 10 positions; blue positive, grey negative weights.
  • Epoch 0 is the random initialisation (AUROC 0.58). After epoch 1 the model reaches 0.79 and after epoch 3 0.85. By epoch 10 the filter has a clear preference, a G at position 7, and the model reaches 0.86.
  • Each step is the update of slide 2.3, applied to all 2,491 weights. We use Adam, a variant of gradient descent that adapts the step size per weight.

5 Look inside

5.1 From a filter to a sequence logo (TODO-4)

  • cutoff_for → windows_above → pwm_of → logo: collect the windows with the highest output, count letters per position
  • Logo height = information content: 2 bits = always the same letter, 0 = all four equally often
  • Left: filter 0’s 40 weights (blue positive, grey negative). Right: its logo, built from the roughly 25,000 windows in bound sequences whose output is above the cutoff (half-way between the filter’s mean and maximum output). The notebook’s count differs slightly because it scans a different subset.
  • The helpers on the slide: cutoff_for sets that cutoff, windows_above collects the 10-letter windows above it, and pwm_of counts the letters at each position. TODO-4a runs these helpers on filter 0 step by step, then consensus_of reads off the most frequent letter at each position; TODO-4b repeats the steps for every filter.
  • Information content at a position is 2 minus the entropy of the letter frequencies, in bits. Each letter’s height is its frequency times that value.
  • A logo shows which windows activate a filter. It leaves out the letters the filter penalises (its negative weights).

5.2 Test a logo: insert it into random RNA (TODO-5)

  • Insert one filter’s consensus 1 to 7 times. Which control shows that its pattern matters?
  • Projected: 1 min.
  • The bar is a 330-letter random RNA sequence; each box is one inserted copy. plant(seqs, motif, copies) writes copy n starting at letter 40 + 45(n − 1), so 7 copies fit. Shaded: letters 150 to 190, where the measured site is in the real data.
  • The consensus is the filter’s most frequent letter at each position: a candidate motif.
  • The question to leave with the room: if the score goes up, is it the pattern or only the letters each copy adds (a U-rich motif adds U letters)? The students design the control in TODO-5b; the notebook states this problem and hints at building it from the motif’s own letters.
  • The intended control is the same letters in another order, inserted at the same places: the difference between the two curves is then what the letter order adds. The debrief slides (6.5, 6.6) show it.
  • This turns a logo, which is only a description of what a filter responds to, into an experiment on the whole model’s output.
